# Release 0.14.0 — pilot hardening

Branch `release/0.14.0` (from the v0.13.1 handover baseline on `main`).
App: versionCode 6, versionName 0.14.0. API contracts unchanged (v0.13.0).

## What changed

### DC app (Android)
| Problem DCs hit | Fix |
|---|---|
| After ~4–5 h on duty the app showed "Not started" and locked the tabs | Day state reads attendance ops directly instead of the last 100 outbox rows |
| Sync could stall: photo batches bigger than the server limit, hot retry loops | 4 MB batch budget, backoff on unruled ops, sync reads only unsent rows |
| Phone storage / memory grew every day (photos kept forever) | Synced photo bytes stripped; synced history older than 7 days deleted |
| Open visit lost when the app was closed; auto check-ins couldn't be closed | Open visit (manual or auto) restored from the phone's journal |
| Logged out in weak network, or by a burst of expired-token calls | Only a real 401/403 on refresh ends the session; refresh uses its own HTTP client (no deadlock) |
| Last ~3 min of route lost at End Day / sign-out | Points are saved before tracking stops; sign-out stops tracking |
| App update could wipe unsynced evidence | Room no longer drops tables on upgrade |
| Xiaomi/Oppo/Vivo battery savers killed tracking | App asks to be exempt from battery optimisation when going on duty |

### Server (API)
- Sync batches containing an unsupported op returned **500** on Postgres (phone retried forever) — migration `009` fixes the constraint.
- A Circle Head could take CSPs from another circle (transfer + Excel import) — now refused.
- OTP: a number locks for 15 min after 5 wrong codes.
- Refuses to start in production without `JWT_SECRET`.
- Bad lat/lng in CSP details import / DC edits rejected; blank cells mean "no change".
- `npm run migrate` is now safe to re-run (tracks applied files; existing DBs are baselined automatically).

### Admin website
- New numbers can register at login (name field appears on "Name Required").
- No more hourly logout: silent token refresh; only a rejected refresh logs out.

## Phone test checklist (do before giving the app to DCs)
Install the 0.14.0 test APK on one Android phone and tick each:
- [ ] Login with OTP (existing DC number) works
- [ ] Check In → tabs unlock; leave the app running **5+ hours** → still "On duty"
- [ ] My CSPs shows addresses; **Get Directions** opens Google Maps to the right place
- [ ] Visit check-in at a CSP → take 2–3 photos → **close the app fully** → reopen → visit still open → Check out
- [ ] Turn mobile data off, do a visit, turn data on → it syncs (dashboard Visits shows it with photos)
- [ ] Battery-optimisation prompt appears once on going on duty
- [ ] End Day → dashboard Attendance shows hours + KM
- [ ] Sign out → tracking notification disappears

## Deploy — server (needs R730 access; follow the R730 SOP)
```sh
# 0. Backup first
TS=$(date +%Y%m%d-%H%M); mkdir -p /home/deepanshu/backups/dc-visits/$TS
cd /home/deepanshu/Csp-Visit-Application/infra/self-hosted
docker compose exec -T postgres pg_dump -U dcvisits dcvisits > /home/deepanshu/backups/dc-visits/$TS/db.sql
docker tag self-hosted-api:latest self-hosted-api:before-$TS

# 1. Get release 0.14.0 code (from the repo/branch this release is pushed to)
#    NOTE: the live server has local edits to compose/nginx not in git — check `git status` first
#    and do NOT `git reset --hard` over them without saving a copy.

# 2. Env: make sure the api service has
#    TRUST_PROXY=1        (fixes "Too Many Requests" for everyone at login — nginx is in front)
#    JWT_SECRET=<existing value>   (the API now refuses to start without it)

# 3. Build, migrate, restart API only
docker compose build api
docker compose run --rm api npm run migrate     # expect: baseline 001–008, applying 009 ok
docker compose up -d --no-deps api

# 4. Verify
curl -sk https://122.176.147.78/dc-visits/healthz        # 200
#    log in on the dashboard; open All CSPs, Attendance
```
**Rollback:** `docker tag self-hosted-api:before-$TS self-hosted-api:latest && docker compose up -d --no-deps api`.
Migration 009 only widens a CHECK constraint, so the old API runs fine on the migrated DB; restore `db.sql` only if data is damaged.

1. Get the **keystore password** for `android/eko-dcvisits.jks` (without it the new APK cannot update the installed app).
2. Build: `./gradlew :app:assembleRelease -PapiBaseUrl=https://122.176.147.78/dc-visits/api/v1/` with the signing env vars (see `android/app/build.gradle.kts`).
3. Install on one phone, run the checklist above, then share the APK with the 12 DCs.
**Rollback:** reinstall `eko-csp-visits-v0.13.1-real-otp.apk` (needs uninstall first because of the lower version; unsynced data on that phone is lost — sync first).

## Known, not fixed in this release
- Hindi added (Profile → Language: System / English / हिंदी); needs a check by a Hindi-speaking DC and on small screens.
- App trusts a self-signed certificate for the raw IP — move to a proper domain + certificate before scaling.
- Photos are stored inside Postgres (fine for 12 DCs; needs object storage at scale).
- A restored auto check-in may get a second (harmless) check-out if the DC also taps Check out.
